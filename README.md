# Graphpaper

CBSE updates, syllabus, papers, question bank and NCERT book links for Classes 1 to 12 (CBSE). The app is `app.css` + `scripts/shell.html` + four scripts loaded in this order: `app.js` (shared core: helpers, class and book pages, router), `parents.js` (Classes 1 to 8), `students.js` (Classes 9 to 12: notices, tracker, syllabus, papers, question bank, subject and chapter pages, calculator) and `boot.js` (loads data, starts the app). Real pages (one per class, stream, section and notice), `sitemap.xml` and `robots.txt` are generated by `scripts/build_site.py`, which the "Build site pages" workflow runs by itself whenever the app or a data file changes. Do not edit generated files (`index.html`, `404.html`, `class-*/`, `notice/`, `board/`, `updates/`, `about/`, `contact/`, `privacy/`, `terms/`, `welcome/`, `calculator/`, `sitemap.xml`, `robots.txt`). Notice URLs use a descriptive slug stored in `updates.json` (`scripts/slugs.py`); the build adds slugs to new notices and keeps old id URLs redirecting in `vercel.json`. To add a page, add it to `routes()` in `scripts/build_site.py`.

## How updates work
- `scripts/scrape_cbse.py` runs on a schedule (`.github/workflows/update.yml`) and adds new CBSE items to `updates.json` as `"status": "pending"`.
- Pending items are never shown. To publish one, edit `updates.json` on GitHub and change `"pending"` to `"approved"` (add a short `summary` if you like).
- You can also run the check by hand: Actions tab > Check CBSE updates > Run workflow.
- The scraper has not been tested against the live CBSE site. If a run adds nothing or fails, check the Actions log.

## Data format (`updates.json`)
```json
{ "id": "unique-id", "tag": "Circular | Date Sheet | Syllabus Change | Result",
  "title": "...", "date": "YYYY-MM-DD", "summary": "...",
  "url": "official link", "status": "approved | pending" }
```
While the file is empty, the site shows clearly labeled sample items.
